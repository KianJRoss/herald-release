# Herald support

Herald is currently beta software.

- Use GitHub Discussions for setup help, architecture questions, and ideas.
- Use GitHub Issues for reproducible bugs and scoped feature requests.
- Use the private process in [SECURITY.md](SECURITY.md) for vulnerabilities.

For a useful bug report, include the Herald version, operating system, Python
or Node version, the command or API route involved, expected and actual
behavior, and a minimal reproduction. Redact API keys, bearer tokens, account
identifiers, private prompts, local paths, tailnet details, and model-provider
session data.

## Modified builds

Official support covers published Herald releases and changes accepted
upstream. You are free to fork or modify Herald, but you maintain the resulting
custom build unless you submit the change as a focused pull request and it is
accepted. Before filing a support request for a modified copy, reproduce the
problem on an unmodified published release.

Projects, integrations, and tools built on top of Herald through documented
interfaces remain normal supported use; this boundary applies to modifications
of Herald itself.

The maintainers cannot guarantee response times, uptime, model availability,
or compatibility with every third-party CLI and provider. Provider billing,
terms, quotas, and data handling remain the user's responsibility.
